# 产品 Agent 输入简报

来源：用户任务书 + 总调度 G0 审计（2026-11-07）

## 1. 产品一句话

一个独立的 macOS 原生 App：在用户主动开始后，录制 FaceTime 通话的**画面 + 对方声音 + 本地麦克风**，录制时用户仍能通过所选扬声器/耳机听到对方，结束后得到一个带两条音轨的 MKV。

## 2. 已确认事实

- 虚拟声卡已安装且可用，但**只有输出，没有输入/loopback**：`com.homepodflow.virtual-audio.surround71.v1`，8ch/48k/Float32。
- 远端声音采集路径为 Core Audio device tap；无 TCC 时回调正常但全零。
- FaceTime 使用系统默认输出，因此必须让用户把默认输出指向虚拟声卡；App 可提供可逆接管。
- 录屏画面已人工验证可录。
- 旧仓库/驱动不得修改；新 App 与新仓库独立；录制 App 与 HomePod Flow 不同时使用。

## 3. 硬性要求

1. 用户主动开始/停止；状态清晰；失败给出具体诊断，不得伪造通过。
2. 视频 ScreenCaptureKit；远端 Core Audio HAL tap；麦克风 Core Audio/AVAudioEngine；监听独立于录制。
3. 实时回调不分配、不加锁、不做文件 IO/网络/日志。
4. 预分配无锁 ring；输入输出独立回调；采样时钟不一致时自适应缓冲+重采样；设备热插拔。
5. 监听时不得把麦克风声音播到扬声器。
6. 输出多音轨，优先 MKV；FFmpeg 可用（`/opt/homebrew/bin/ffmpeg`）。
7. 录制中可关闭/开启监听，不影响音轨。
8. 必须能解释“为什么没录到”：权限、路由、格式、设备忙、时钟不连续。

## 4. 需要产品 Agent 收敛的问题

- V1 的最小可用范围（必须做/可以延后）。
- 默认输出接管的产品交互与失败恢复（崩溃后）。
- 8ch 设备对 FaceTime 立体声的取声道策略与用户可见说明。
- 监听默认值、缓冲目标、音量/静音交互。
- 麦克风 AEC 的产品表述：Apple VPIO 与 WebRTC AEC3 的差异如何对用户说明。
- 录制文件组织、命名、失败时的半成品处理。
- 权限引导流程（麦克风、音频录制、屏幕录制）与拒绝后的降级。
- 验收口径：哪些必须真人通话验证，哪些可自动化。

## 5. 交付格式

`PRD.md`：
- 用户画像与三个核心场景
- 功能清单（P0/P1/P2）与明确 Non-goals
- 主流程、异常流程、状态机
- 验收标准（可测）
- 文案（中文）与风险声明

`TECH_PLAN.md`：
- 模块图与数据流（远端/麦克风/监听/视频/封装）
- 线程与缓冲模型、时钟与漂移策略
- 权限与 TCC 处理
- 失败分类与诊断字段
- 与现有 AudioProbe/CRing 的复用关系
- 分阶段实施顺序与每阶段验证命令

`HANDOFF.md`：给 UI 与 Dev 的交接清单（含 open questions）。
