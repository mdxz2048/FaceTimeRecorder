## 0. 设计基线：轻、浅、像 macOS 原生小工具

### 0.1 视觉

| 维度 | 规范 |
|---|---|
| 参照 | macOS 系统设置、QuickTime Player、语音备忘录的原生单窗口工具 |
| 主色 | 系统强调色（默认蓝色）；录制态用系统红色；警告用系统橙色 |
| 背景 | `NSColor.windowBackgroundColor`；不铺卡片、不加渐变、不加大面积阴影 |
| 字体 | 系统字体（SF Pro）；标题 20 pt Semibold，正文 13 pt，辅助 11 pt |
| 控件 | 原生复选框、原生主按钮、原生工具栏菜单；不用自绘大开关、仪表盘、卡片墙 |
| 外观 | 浅色为设计与验收基线；跟随系统外观，深色只保证语义色可读 |
| 窗口 | 单窗口、单列、无侧栏、无标签页、无设置窗口、无高级区 |

### 0.2 主窗口

| 项 | 值 |
|---|---|
| 默认尺寸 | 400 × 300 pt |
| 最小尺寸 | 360 × 260 pt |
| 最大宽度 | 460 pt |
| 内容边距 | 左右 24 pt，上下 20 pt |
| 滚动 | 不滚动 |
| 多开 | 禁止；第二个实例只唤醒已有窗口 |

### 0.3 主界面线框

```text

│  FaceTime 录音                 …   │
│                                    │
│  ☑ 录制对方声音                     │

│                                    │

│  │           开始录制            │  │

```

### 0.4 主界面只允许出现的元素

1. 标题：`FaceTime 录音`。
2. 两个复选框/开关：`录制对方声音`、`录制我的麦克风`，默认都勾选。
3. 一个全宽主按钮：`开始录制` / `停止并保存` / `取消` / `正在保存…` / `再录一次` / `重试`。
4. 一行状态：圆点 + 文字 + 计时（录制中）。
5. 一行小字：`请确保对方已知情并同意录音。`
6. 右上角 `…` 菜单。
7. 完成时的一行结果：`已保存 FaceTime.mp4（双方声音）` + `在 Finder 中显示`。

主界面不出现：副标题、说明段、高级入口、设备/窗口/显示器选择、权限面板、权限状态、诊断按钮、MKV/WAV 行、播放按钮、文件大小/时长详情、Beta 行。

### 0.5 右上角“…”菜单

只允许以下三项：

| 菜单项 | 行为 |
|---|---|
| `复制诊断` | 复制当前会话诊断/日志到剪贴板 |
| `在 Finder 中显示诊断` | 打开会话目录或诊断文件；没有会话时打开支持目录 |
| `关于 FaceTime Recorder` | 版本号 + `Beta · 远端音频待真人通话验收` |

没有“打开系统设置”“重新检查权限”“选择设备/窗口”等菜单项。用户不需要通过菜单完成正常录制。

### 0.6 可访问性

- 两个复选框必须有可读标签，VoiceOver 读作“录制对方声音，复选框，已勾选”。
- 主按钮支持 `Return`；空格切换当前聚焦复选框。
- 录制中不能只靠红点表达，必须有 `录制中` 文字与计时。
- 支持增强对比度与减弱动态效果。
- `…` 菜单有可读标签，不只用图标。

## 1. 一句话定位与三个场景

### 1.1 一句话定位

**一个只问两件事的轻巧录屏工具：录不录对方、录不录我，按一次开始。**

用户不需要理解声卡、路由、监听、AEC、窗口选择或权限矩阵。App 自己找 FaceTime、自己采集、自己整理文件。

### 1.2 三个场景

| 场景 | 用户目标 | 操作 | 结果 |
|---|---|---|---|
| **异地家人/朋友通话留档** | 把一段有画面的通话直接发给家人或自己回看 | 两项默认勾选 → 开始 → 停止 | `FaceTime.mp4`，默认播放双方混音 |
| **远程采访 / 播客 / 口述记录** | 后期想单独听对方或自己 | 两项勾选 → 开始 → 停止 | MP4 含 Mix / Remote / Mic 三轨；会话目录保留原始 WAV |
| **只留一方声音** | 只想留对方，或只想录自己；不想改系统声音、不想装虚拟声卡 | 只勾一项 → 开始 → 停止 | 单方 MP4；不请求无关权限 |

### 1.3 承诺与非承诺

**承诺：** 不接管系统输出，FaceTime 声音不中断；不要求虚拟声卡；不需要设备/窗口/权限配置；停止后给出可播放 MP4，或一句明确原因 + 重试；失败时原始 WAV 留在会话目录。

**非承诺：** 不承诺消除外放回声；不承诺对方全程静音时仍能录到对方；不承诺对方同意，同意提示只是一行提醒。

## 2. 首启 / 空闲 / 准备 / 录制 / 停止 / 完成 / 失败状态机

### 2.1 状态图

```text
首启 ──加载设置，不请求权限──► 空闲
空闲 ──点开始，且至少勾一项──► 准备中
准备中 ──所需轨道首帧就绪──► 录制中
准备中 ──用户取消──► 空闲
准备中 ──硬错误──► 失败
录制中 ──停止 / 退出 / 通话进程结束 / 睡眠──► 停止
停止 ──MP4 生成成功──► 完成
停止 ──MP4 生成失败──► 失败
完成 ──再录一次──► 准备中
完成 ──修改勾选──► 空闲
失败 ──重试──► 准备中
失败 ──修改勾选──► 空闲
```

### 2.2 状态表

| 状态 | 状态行 | 主按钮 | 两个复选框 | 结果行 | 允许的动作 |
|---|---|---|---|---|---|
| **首启** | `准备就绪`；若没有 FaceTime 窗口，显示 `准备就绪 · 先在 FaceTime 中拨通或接听` | `开始录制` | 可切换，默认都勾选 | 无 | 勾选、开始 |
| **空闲** | `准备就绪`；两项都关时 `请至少勾选一项声音。` | `开始录制`（两项都关时禁用） | 可切换 | 上次结果保留一行 | 勾选、开始 |
| **准备中** | `正在准备…` 或当前子步骤一句话 | `取消` | 锁定 | 无 | 取消；等待系统授权 |
| **录制中** | `录制中 00:12`；异常时同一行追加短提示 | `停止并保存`（红色） | 锁定 | 无 | 停止 |
| **停止** | `正在保存…` | `正在保存…`（禁用） | 锁定 | 无 | 等待；退出时确认后等待 |
| **完成** | `已保存 FaceTime.mp4（双方声音）` + `在 Finder 中显示` | `再录一次` | 解锁 | 与状态行同一行 | Finder、改勾选、再录 |
| **失败** | 一句可行动原因 | `重试` | 解锁 | 无 | 重试、改勾选、诊断菜单 |

### 2.3 首启

- 第一次打开只加载设置、检测环境，**不请求任何权限**，不弹权限预检页，不做 onboarding。
- 两项默认勾选；用户通常只需要点开始。
- 若检测不到 FaceTime 窗口，状态行显示 `准备就绪 · 先在 FaceTime 中拨通或接听`；不阻止开始。
- 第一次点“开始录制”后，才按第 6 节请求所需权限。
- 没有“高级”“设置”“权限”入口；首启完成后不再显示额外提示。

### 2.4 空闲

- 两个复选框可切换；切换只影响下一次录制。
- 两项都关：主按钮禁用，状态行 `请至少勾选一项声音。`；不弹窗、不跳设置。
- 对方声音开启但没有 FaceTime 窗口：仍可开始；准备阶段若没有读到对方声音，只在状态行追加一句，不阻塞、不弹确认框。
- 麦克风权限已拒绝：自动取消麦克风勾选，状态行 `麦克风权限未开启，本次只录对方声音。`；开始时不重复弹系统授权。
- 系统音频权限已拒绝：自动取消对方声音勾选；若麦克风仍开启，状态行 `无法读取对方声音，本次只录你的麦克风。`；若两项都不可用，进入失败态。
- 屏幕权限已拒绝：本次自动改为只录音频，状态行 `屏幕录制权限未开启，本次只录声音。`；不阻止开始。

### 2.5 准备中

准备中只用一行状态显示当前动作，不上报技术细节：

| 子步骤 | 状态行 | 说明 |
|---|---|---|
| 1. 检查环境 | `正在准备…` | 找 FaceTime 窗口与 `avconferenced` |
| 2. 请求权限 | `等待系统授权…` | 只在缺权限时出现；系统弹窗期间不计超时 |
| 3. 建立远端采集 | `正在读取对方声音…` | process tap + 首帧 |
| 4. 准备画面 | `正在准备画面…` | 自动找 FaceTime 窗口；找不到则主显示器 |
| 5. 启动麦克风 | `正在准备麦克风…` | 仅麦克风开启时 |
| 6. 开始 | `即将开始…` | 所需轨道首帧就绪后进入录制 |

规则：

- 计时从所需轨道首帧就绪后开始，不从点击按钮开始。
- 音频先于视频启动，避免片头无声画面。
- 准备中可点 `取消`；取消后删除空会话目录，回到空闲。
- 权限等待不自动超时；除权限等待外，10 秒内没有任何音频回调/首帧 → 失败 `声音连接没有建立，请重试。`。只是对方暂时静音、但 tap 有回调，不算失败。
- 权限拒绝不弹错误卡；按第 6 节用一句状态说明并降级。
- 远端 2.5 秒无信号不弹确认框；状态行显示 `还没有听到对方声音，仍会继续录制。`，继续进入录制。

### 2.6 录制中

- 红点 + `录制中 MM:SS`；计时每秒更新。
- 两个复选框锁定；点击无效，不解释技术原因。
- 主按钮变红，文案 `停止并保存`。
- 远端连续 10 秒无信号：状态行变为 `录制中 00:12 · 未检测到对方声音`；只提示，不停止。
- FaceTime 窗口关闭/最小化：自动切主显示器；状态行 `录制中 00:12 · 已切到主显示器`；不停止。
- `avconferenced` 进程结束：自动停止并保存；完成后仍只显示一行保存结果。
- 系统睡眠/合盖：唤醒后自动停止并保存；完成后仍只显示一行保存结果。
- 用户切换耳机/扬声器：不影响 process tap；不提示、不恢复、不中断。

### 2.7 停止

- 点 `停止并保存` 后立即禁用主按钮，状态行 `正在保存…`。
- 不允许取消；强退可能丢失封装，但原始 WAV/MOV 仍留在会话目录。
- 用户点关闭窗口或 `⌘Q`：原生确认 `正在录制。退出会停止并保存。`；按钮 `停止并保存并退出` / `取消`；选择前者后等待保存完成再退出。
- MP4 生成失败：进入失败态，状态行 `声音和画面已保留，但 MP4 生成失败，请重试。`；主按钮 `重试`；诊断菜单可查日志。

### 2.8 完成

- 完成态没有单独的 `完成` 状态行；只显示一行保存结果：`已保存 FaceTime.mp4（双方声音）` + `在 Finder 中显示`。
- 主按钮 `再录一次`；两个复选框解锁。
- 没有播放按钮、没有 MKV/WAV 行、没有文件大小/时长详情、没有“打开会话文件夹”第二个按钮。
- 原始 WAV 留在会话目录；需要时通过 `…` 菜单 → `在 Finder 中显示诊断` 或 Finder 自行进入会话目录。

### 2.9 失败

- 状态行只显示一句可行动原因；主按钮只显示 `重试`。
- 不显示错误标题、错误码、技术详情、多个操作按钮、设置跳转。
- 诊断和内部错误码只进 `…` 菜单。
- 失败后两个复选框解锁；用户可修正勾选后重试。
- 原始 WAV/MOV 留在会话目录，不自动删除。

### 2.10 异常退出

- 不做启动恢复向导、不弹“上次录制未完成”卡片。
- 异常退出的原始 WAV/MOV 留在会话目录；用户可通过 Finder 或 `…` 菜单找到。
- 不自动封装、不自动恢复、不增加主界面元素。

## 3. 用户动作 ≤3 步

| 步骤 | 首次使用 | 之后 |
|---|---|---|
| 1 | 在 FaceTime 中拨通或接听 | 在 FaceTime 中拨通或接听 |
| 2 | 确认两个复选框（默认已勾选，通常不用动） | 无需操作 |
| 3 | 点 `开始录制` | 点 `开始录制` |

停止只需要再点一次 `停止并保存`。

计数口径：

- 产品内配置步骤 ≤3；不包含启动 App、不包含在 FaceTime 里建立通话。
- 首次系统授权弹窗是 macOS 强制步骤，最多 3 个，每个点一次“允许”；App 不额外加权限预检页或设置向导。
- 没有“高级”“设备”“窗口”“权限”步骤；正常录制永远不需要打开 `…` 菜单。
- 权限拒绝时只显示一句状态并降级，不要求用户进入设置页面才能继续。

键盘：

| 操作 | 快捷键 |
|---|---|
| 开始录制 | `⌘R` |
| 停止并保存 | `⌘.` |
| 在 Finder 中显示上次结果 | `⌘⇧F` |

菜单只保留“录制”和“窗口/帮助”；删除“恢复默认音频输出”“刷新音频设备”“打开声音设置”等 V1 遗留项。

## 4. 自动行为

### 4.1 总览

| 自动行为 | 触发 | App 做什么 | 用户看到什么 |
|---|---|---|---|
| 找通话进程 | 每次开始 | 查找 FaceTime 窗口；查找 `avconferenced`；PID → process object | `正在准备…` |
| 采集对方声音 | 对方开启 | process tap + 私有 aggregate；48 kHz / 2ch / Float32 | 不需要任何设备选择 |
| 3ch 麦克风降单声道 | 麦克风开启 | 3 通道 → 单声道 → 48 kHz 立体声；+12 dB；限幅 | 不需要调增益 |
| 自动找画面 | 每次开始 | 优先 `com.apple.FaceTime` 窗口；找不到回退主显示器 | 不需要选窗口 |
| 混音/分轨 | 停止后 | Remote + Mic 对齐；MP4 三音轨；Mix 默认播放 | `正在保存…` |
| 输出不中断 | 全程 | 不接管系统输出、不监听、不回放麦克风 | FaceTime 声音照常播放 |

### 4.2 对方声音：`avconferenced` process tap

正式链路：

```text
FaceTime 通话
  ↓
/usr/libexec/avconferenced
  ↓ pgrep -x avconferenced → PID
  ↓ kAudioHardwarePropertyTranslatePIDToProcessObject
Core Audio process object
  ↓ CATapDescription(stereoMixdownOfProcesses: [processObject])
AudioHardwareCreateProcessTap
  ↓ 私有 Aggregate Device（物理输出作时钟）
AudioDeviceCreateIOProcID
  ↓
48 kHz / 2ch / Float32 PCM → remote.wav
```

规则：

- 不要求 HomePod Flow 或其他虚拟声卡；启动、开始、停止都不依赖虚拟设备。
- 不修改系统默认输出；不创建输出租约；崩溃不会让 Mac 静音。
- 录制中切换耳机/扬声器不影响采集。
- 不使用 App 内监听；FaceTime 自己播放，麦克风永不进入监听。
- 不添加 AEC；FaceTime 自带的回声处理继续生效，App 不承诺消除外放回声。
- 启动阶段只校验有回调 + 有帧；远端全零不阻塞，只在状态行提示，完成后按实际结果标注。
- 停止时若远端全程为零，完成行写 `已保存 FaceTime.mp4（未录到对方声音）`，不得写“双方声音”。

### 4.3 麦克风：3ch → 单声道

目标行为（V2 验收口径）：

1. 打开当前系统默认输入，不要求用户选择。
2. 内置麦克风常见为 3 通道阵列；不得只取 ch0。
3. 3 通道降为单声道：优先按通道能量加权混合；若相位抵消明显（混合后 RMS 低于最大单通道的 50%），回退到能量最大的单通道；切换通道时做 20–50 ms 平滑。
4. 单声道复制为 48 kHz / 2ch Float32，写入 `microphone.wav`。
5. 软件增益 +12 dB，后接 limiter，峰值限制在 -1 dBFS 附近。
6. 不提供增益滑杆；没有权限面板可以查看峰值。

> **实现现状提醒**：当前 `MicCaptureRecorder` 仍只取 `ch0`，没有 +12 dB 与 limiter。AC-09 以 V2 目标为准；修正前不得宣称已解决“麦克风偏小”。

### 4.4 画面：自动找 FaceTime

1. 开始录制时用 ScreenCaptureKit 列出屏幕上的窗口。
2. 优先匹配 bundle id `com.apple.FaceTime`；其次匹配应用名包含 `FaceTime` 的窗口。
3. 找到窗口：录该窗口，按屏幕 backing scale 输出原生像素（Retina 为 2×）；30 fps；约 20 Mbps。
4. 找不到窗口：回退主显示器；状态行 `正在准备画面…` 后继续，不阻止录制；完成后不额外解释。
5. 录制中窗口关闭/最小化：自动切主显示器继续，状态行 `录制中 00:12 · 已切到主显示器`；不停止。
6. 没有窗口选择器、没有显示器选择器；用户不能也不需要在 App 里改画面源。

### 4.5 混音与 MP4 三音轨

录制阶段：

- 远端写 `remote.wav`；
- 麦克风写 `microphone.wav`；
- 画面写 `screen.mov`；
- 不实时混音。

停止后：

1. 用 host time 计算视频首帧、远端首样本、麦克风首样本偏移；
2. 用 FFmpeg `-itsoffset` 对齐；
3. 用 `amix=inputs=2:duration=longest:normalize=0` 生成 Mix，后接 `alimiter=limit=0.95`；
4. 输出 MP4：H.264 + AAC 音轨；
5. 两项都开启时，音轨顺序固定：

| 音频轨序号 | 内容 | 默认播放 | 标题 |
|---|---|---|---|
| 0 | Mix（对方 + 麦克风） | 是（`default`） | `Mix` |
| 1 | Remote（对方） | 否 | `Remote` |
| 2 | Microphone（你） | 否 | `Microphone` |

6. 只开一项时，只生成 1 条 `Mix` 音轨（内容就是该源），不生成空的/重复的 Remote/Mic 轨。
7. 原始 WAV 保留在会话目录，不删除。
8. **不生成 MKV**；MP4 三音轨就是 V2 的唯一交付格式。

播放行为：

- QuickTime 默认播放 `Mix`；Remote/Mic 存在但不自动播放。
- 用户可在播放器的“音轨/声道”菜单里切到 Remote 或 Mic。
- 某些第三方播放器可能忽略 `default` 标记并列出全部音轨；验收以 QuickTime + `ffprobe` 的 disposition 为准。

### 4.6 启动顺序

```text
检查勾选
  → 按需请求权限（麦克风 → 系统音频 → 屏幕）
  → 建立 process tap / 首帧
  → 打开麦克风 / 首帧
  → 准备画面 / 首帧
  → 开始计时
```

不需要的轨道不启动、不请求权限；权限拒绝按第 6 节降级；任何硬错误都只显示一句失败原因 + 重试。

### 4.7 文件布局

```text
~/Movies/FaceTime Recorder/
  2026-11-08 21-30-05/
    FaceTime.mp4          # 唯一主交付；默认播放 Mix
    remote.wav            # 对方原始音频，48 kHz / 32-bit float
    microphone.wav        # 麦克风原始音频，48 kHz / 32-bit float
    screen.mov            # 中间视频，供重新封装
    diagnostics.json      # 诊断
```

- 不生成 `FaceTime.mkv`。
- 会话目录按开始时间命名；同名不覆盖，自动加序号。
- 原始 WAV 与 `screen.mov` 默认保留；不在录制结束后自动清理。
- 主界面不显示路径；Finder 按钮直接选中 MP4。

## 5. 四种开关组合的行为与文案

### 5.1 总表

| 录制对方 | 录制麦克风 | 需要的权限 | MP4 音轨 | 完成行 | 说明 |
|---|---|---|---|---|---|
| 开 | 开 | 系统音频 + 屏幕 + 麦克风 | 3 轨：Mix / Remote / Mic | `已保存 FaceTime.mp4（双方声音）` | 默认组合；Mix 默认播放 |
| 开 | 关 | 系统音频 + 屏幕 | 1 轨：Mix（对方） | `已保存 FaceTime.mp4（对方声音）` | 不请求麦克风；不造空 Mic 轨 |
| 关 | 开 | 屏幕 + 麦克风 | 1 轨：Mix（你） | `已保存 FaceTime.mp4（你的声音）` | 不请求系统音频；不造空 Remote 轨 |
| 关 | 关 | 无 | 不开始 | 状态行 `请至少勾选一项声音。` | 按钮禁用，不弹窗 |

> “MP4 三音轨”指默认组合（两项都开）。只开一项时只生成一条 Mix 轨，避免空轨和重复轨；原始 WAV 仍在会话目录。

### 5.2 开 + 开（默认）

- 复选框：`录制对方声音`、`录制我的麦克风` 都勾选。
- 行为：process tap + FaceTime 窗口 + 3ch 麦克风；停止后 MP4 三轨，Mix 默认播放，Remote/Mic 非默认。
- 权限：系统音频、屏幕、麦克风都按需请求；任一拒绝按第 6 节降级。
- 完成行：`已保存 FaceTime.mp4（双方声音）` + `在 Finder 中显示`。
- 若远端全程无声：完成行 `已保存 FaceTime.mp4（未录到对方声音）`。
- 若麦克风全程无声：完成行 `已保存 FaceTime.mp4（未录到麦克风声音）`。

### 5.3 开 + 关（只录对方）

- `录制我的麦克风` 不勾选；不请求麦克风权限。
- 行为：只采集对方 + 画面；MP4 一条 Mix（对方）；会话目录保留 `remote.wav`。
- 完成行：`已保存 FaceTime.mp4（对方声音）`。
- 若远端全程无声：完成行 `已保存 FaceTime.mp4（未录到对方声音）`。
- 若屏幕权限拒绝：自动改为只录音频；完成行 `已保存 FaceTime.mp4（对方声音，无画面）`。

### 5.4 关 + 开（只录麦克风）

- `录制对方声音` 不勾选；不查找 `avconferenced`、不请求系统音频权限、不需要通话进行中。
- 行为：只采集麦克风 + 画面；MP4 一条 Mix（你）；会话目录保留 `microphone.wav`。
- 完成行：`已保存 FaceTime.mp4（你的声音）`。
- 若屏幕权限拒绝：自动改为只录音频；完成行 `已保存 FaceTime.mp4（你的声音，无画面）`。

### 5.5 关 + 关

- 主按钮禁用，状态行 `请至少勾选一项声音。`
- 不弹窗、不跳设置、不创建会话目录。
- 键盘 `⌘R` 也不启动。

### 5.6 组合切换规则

- 空闲/完成/失败态可切换；切换只影响下一次录制。
- 准备中/录制中/停止中锁定；点击无效。
- 录制中不允许“补勾”另一方；要改组合必须停止并保存，再开始新会话。
- 完成后改勾选，结果行收成上次那一行，不静默删除文件。

## 6. 权限最小化

### 6.1 原则

1. 启动不请求权限；只在点“开始录制”且该权限对应的轨道开启时才请求。
2. 不需要的轨道不请求：麦克风关闭不请求麦克风；对方声音关闭不请求系统音频。
3. 一次只弹一个系统权限；顺序：麦克风 → 系统音频 → 屏幕。
4. 拒绝后不反复弹、不显示权限面板、不提供“打开设置”按钮；只用一句状态说明并降级。
5. 从系统设置授权后回到 App，重新点开始即可；屏幕权限在部分 macOS 版本需要重启 App，状态行会说 `屏幕录制权限未开启，本次只录声音。`。
6. 不请求辅助功能、完全磁盘访问、自动化、通知等无关权限。

### 6.2 权限表

| 权限 | 何时请求 | 不请求的情况 | 拒绝后的行为 | 状态行一句话 |
|---|---|---|---|---|
| **麦克风** | 第一次开始且麦克风勾选 | 麦克风未勾选；已拒绝 | 自动取消麦克风勾选，降级为仅对方；继续录制 | `麦克风权限未开启，本次只录对方声音。` |
| **系统音频录制** | 第一次开始且对方声音勾选 | 对方声音未勾选；已拒绝 | 若麦克风可用，自动取消对方勾选，降级为仅麦克风；否则失败 | `无法读取对方声音，本次只录你的麦克风。` |
| **屏幕录制** | 第一次开始且需要画面 | 用户已拒绝后本次只录音频 | 自动关闭画面，继续录音频；不阻止开始 | `屏幕录制权限未开启，本次只录声音。` |

### 6.3 首次开始的顺序

```text
点“开始录制”
  → 麦克风（仅勾选时）
  → 系统音频（仅对方声音勾选时）
  → 屏幕录制（仅需要画面时）
  → 所需轨道就绪后开始写文件、计时
```

说明：

- 系统音频权限没有可靠预检 API；通过一次短暂 process tap 触发系统授权，确认后正式启动采集。用户只看到一次系统弹窗。
- 屏幕权限被拒绝时本次自动只录音频，完成行带 `无画面`；下次开始会再次按需尝试，不弹权限面板。
- 权限全部就绪前不创建 MP4，避免空文件。
- 如果两项声音都不可用（麦克风拒绝且对方声音也拒绝），失败态一句 `没有可用的声音来源，请允许麦克风或系统音频录制后重试。` + `重试`。

### 6.4 拒绝后的降级矩阵

| 组合 | 麦克风拒绝 | 系统音频拒绝 | 屏幕拒绝 |
|---|---|---|---|
| 开 + 开 | 仅对方，继续 | 仅麦克风，继续 | 只录声音，继续 |
| 开 + 关 | 不涉及 | 失败（没有可用音轨） | 只录声音，继续 |
| 关 + 开 | 失败（没有可用音轨） | 不涉及 | 只录声音，继续 |
| 关 + 关 | 不开始 | 不开始 | 不开始 |

### 6.5 不做的事

- 不做权限面板、权限矩阵、绿色/橙色状态点。
- 不做“打开系统设置”按钮或深链跳转。
- 不在主界面显示 TCC 名称、设备名、进程名、OSStatus。
- 不把用户拒绝权限称为“App 故障”。

## 7. 中文错误文案

### 7.1 规则

- 失败只在状态行显示一句可行动原因；按钮只有 `重试`。
- 不显示错误标题、错误码、技术详情、多个操作按钮。
- 不出现：`OSStatus`、`fourCC`、`-10877`、`!obj`、`kAudio...`、`tap`、`aggregate`、`avconferenced`、`8ch`、`AEC`、`虚拟声卡`。
- 技术细节只进 `…` 菜单 → `复制诊断` / `在 Finder 中显示诊断`。
- 能降级的权限拒绝不算失败；只有没有可用音轨、磁盘、封装等硬错误才进入失败态。

### 7.2 失败文案

| 触发 | 状态行（唯一一句） | 按钮 |
|---|---|---|
| 麦克风拒绝且对方声音也拒绝 | `没有可用的声音来源，请允许麦克风或系统音频录制后重试。` | `重试` |
| 10 秒内没有任何音频回调/首帧 | `声音连接没有建立，请重试。` | `重试` |
| 磁盘空间不足 | `磁盘空间不足，请清理后重试。` | `重试` |
| MP4 生成失败 | `声音和画面已保留，但 MP4 生成失败，请重试。` | `重试` |
| 录制不足 2 秒 | `录制时间太短，请重新录制。` | `重试` |
| 保存时没有可用素材 | `没有录到可保存的内容，请重试。` | `重试` |
| 其他未知失败 | `保存没有完成，请重试。` | `重试` |

### 7.3 非失败提示（只在状态行）

| 触发 | 状态行 |
|---|---|
| 麦克风权限拒绝 | `麦克风权限未开启，本次只录对方声音。` |
| 系统音频权限拒绝、麦克风可用 | `无法读取对方声音，本次只录你的麦克风。` |
| 屏幕权限拒绝 | `屏幕录制权限未开启，本次只录声音。` |
| 启动阶段 2.5 秒无远端信号 | `还没有听到对方声音，仍会继续录制。` |
| 录制中 10 秒无远端信号 | `录制中 00:12 · 未检测到对方声音` |
| 找不到 FaceTime 窗口 | `录制中 00:12 · 已录主显示器` |
| 窗口消失 | `录制中 00:12 · 已切到主显示器` |
| 通话进程结束 | 自动停止并保存；完成后正常显示保存行 |
| 系统睡眠 | 自动停止并保存；完成后正常显示保存行 |

### 7.4 语气

- 用“你”，不用“您”；短句，不甩术语。
- 先说发生了什么，再说可以怎么做。
- 不指责用户，不写“操作错误”“非法配置”。
- 失败时保留希望：`声音和画面已保留`、`请重试`。

## 9. Non-goals

以下内容 V2 明确不做，不得在 UI、文案、发布说明中暗示支持：

### 9.1 配置与界面

- 不做高级区、设置窗口、偏好设置、侧栏、卡片墙、仪表盘；
- 不做设备选择、远端设备选择、麦克风选择；
- 不做窗口选择、显示器选择、画面源选择；
- 不做权限面板、权限矩阵、权限状态点、设置向导；
- 不做“打开系统设置”按钮或深链引导；
- 不做主题、皮肤、深色主题单独设计。

### 9.2 音频

- 不做 AEC / 回声消除 / 降噪 / 自动增益开关；
- 不做监听输出选择、监听音量、系统输出接管；
- 不做虚拟声卡、虚拟麦克风、驱动安装；
- 不做实时混音、实时波形、多轨时间线、分轨音量/静音；
- 不做 FaceTime 之外的应用音频采集（Zoom、微信、Teams、浏览器等）。

### 9.3 输出

- 不生成 MKV；MP4 三音轨是唯一交付格式；
- 不做 MKV 多轨归档、MKV 播放器、MKV 提取向导；
- 不做完成页文件列表、播放按钮、文件大小/时长详情；
- 不做云端上传、分享链接、团队空间。

### 9.4 内容与平台

- 不做语音转文字、翻译、摘要、说话人分离；
- 不做视频剪辑、裁剪、拼接、字幕、转场、画中画；
- 不做 4K / 60 fps / HDR / 多显示器拼接 / 直播推流；
- 不做 iOS / iPadOS / Windows / Web；
- 不做菜单栏常驻录制器、后台偷录、开机自启、多会话并行。

### 9.5 合规与同意

- 不做“对方同意”勾选框或开始前同意弹窗；
- 不判断录音是否合法，不提供隐蔽录制；
- 不绕过系统录音指示、不隐藏麦克风/屏幕录制状态；
- 只保留一行 `请确保对方已知情并同意录音。`

## 10. 可测验收标准

### 10.1 验收前置

- 两台设备可进行 FaceTime 通话，或一台 Mac + 一台 iPhone；
- 至少一条内置麦克风为 3 通道的 MacBook；
- 安装 FFmpeg，或 App 内置可用的封装组件；
- 测试机首次安装 App，TCC 权限为未请求状态；
- 记录测试前系统默认输出设备名称/UID。

### 10.2 功能验收

| 编号 | 场景 | 步骤 | 通过标准 |
|---|---|---|---|
| **AC-01** | 主界面极简 | 打开 App，截图 | 只有标题、两个复选框、主按钮、一行状态、一行同意提示、右上角 `…`；没有高级/设置/设备/窗口/权限面板 |
| **AC-02** | 首启不请求权限 | 全新安装后首次打开，观察 10 秒 | 不出现任何系统权限弹窗；不出现权限预检页；两个复选框默认勾选 |
| **AC-03** | 三步主路径 | 发起 FaceTime → 保持默认勾选 → 点开始 → 说 30 秒 → 停止 | App 内配置点击 ≤1 次；3 秒内进入录制（首次授权除外）；MP4 可播放且双方声音都有 |
| **AC-04** | 状态机 | 依次触发空闲、准备、录制、停止、完成、失败 | 状态行、主按钮、复选框锁定符合第 2 节；准备中可取消；停止中不可取消；失败只有一句 + 重试 |
| **AC-05** | 四组合产物 | 分别用 开+开 / 开+关 / 关+开 / 关+关 录制 10 秒 | 开+开生成 3 音轨 MP4；开+关、关+开生成 1 音轨 MP4；关+关按钮禁用且不创建会话目录 |
| **AC-06** | MP4 三轨与默认播放 | 开+开 录制后执行 `ffprobe`，再用 QuickTime 打开 | 3 条音频流；`a:0` 的 `default=1`，`a:1/a:2` 的 `default=0`（ffprobe 音频流 index 通常为 1/2/3）；QuickTime 默认只播 Mix；切轨能单独听 Remote/Mic |
| **AC-07** | 不生成 MKV | 完成一次开+开 录制，检查会话目录 | 目录中没有 `FaceTime.mkv`；只有 `FaceTime.mp4`、原始 WAV、`screen.mov`、诊断 |
| **AC-08** | process tap 非零 | 真人通话中录制 30 秒，双方说话 | `remote.wav` 帧数 > 0，RMS > 0.005，峰值 < 1.0；MP4 默认音轨能听到对方 |
| **AC-09** | 3ch 麦克风 | 用内置 3 通道麦克风录制正常说话 30 秒 | `microphone.wav` 非零；不是只取 ch0 的弱信号；峰值 ≤ -1 dBFS 附近且不削波；双方混音响度差 ≤6 dB（主观） |
| **AC-10** | 不接管系统输出 | 录制前后记录默认输出 | 录制前后默认输出名称/UID 完全一致；录制中切换耳机不中断；App 崩溃后 Mac 仍有声音 |
| **AC-11** | 自动找窗口 | 打开 FaceTime 窗口后开始；再关闭窗口录 10 秒 | 有窗口时视频为该窗口原生像素（Retina 2×）；关闭后自动切主显示器并更新状态行；录制不中断 |
| **AC-12** | 权限按需 | 分别测试：只对方、只麦克风、两项都开 | 只对方不弹麦克风；只麦克风不弹系统音频；两项都开最多弹 3 个且串行；没有权限面板 |
| **AC-13** | 拒绝降级 | 分别拒绝麦克风、系统音频、屏幕 | 麦克风拒绝 → 仅对方继续；系统音频拒绝 → 仅麦克风继续；屏幕拒绝 → 只录音频继续；每次只有一句状态说明，不跳设置 |
| **AC-14** | 失败只一句 + 重试 | 触发无可用音轨、磁盘不足、MP4 生成失败 | 状态行只有一句可行动原因；主按钮只有 `重试`；无错误标题/错误码/多个操作 |
| **AC-15** | 完成页只一行 | 开+开 完成一次 | 只有 `已保存 FaceTime.mp4（双方声音）` + `在 Finder 中显示`；无 MKV/WAV 行、播放按钮、文件大小/时长 |
| **AC-16** | 诊断菜单 | 点右上角 `…` | 只有 `复制诊断`、`在 Finder 中显示诊断`、`关于 FaceTime Recorder`；关于里有 Beta 待验收文字 |
| **AC-17** | 错误文案 | 触发所有失败，截图/OCR | 主界面无 `OSStatus`、`-数字`、`kAudio`、`tap`、`aggregate`、`avconferenced`、`8ch`、`AEC`、`虚拟声卡` |
| **AC-18** | 长时间稳定性 | 连续录制 15 分钟，双方交替说话 | 音画偏差 ≤100 ms；MP4 可完整播放；无持续增长的内存/丢帧；远端与麦克风无逐渐漂移 |
| **AC-19** | 真人通话签字 | 1 分钟真实 FaceTime，双方说话，回放 | 双方声音清晰可辨；无 App 新增回声；远端不是静音；总调度书面签字后方可移除 Beta 文字 |

### 10.3 产物检查命令

```sh
# MP4 音频流与 default disposition
ffprobe -v error \
  -show_entries stream=index,codec_type:stream_disposition=default \
  -of json "FaceTime.mp4"

# 视频分辨率
ffprobe -v error -select_streams v:0 \
  -show_entries stream=width,height,r_frame_rate \
  -of default=nw=1 "FaceTime.mp4"

# 远端 WAV 电平
ffmpeg -hide_banner -i remote.wav -af volumedetect -f null - 2>&1 | tail -20

# 麦克风 WAV 电平
ffmpeg -hide_banner -i microphone.wav -af volumedetect -f null - 2>&1 | tail -20
```

预期（开+开）：

- 3 条 `codec_type=audio`；
- `index=1` 的 `default=1`，`index=2/3` 的 `default=0`（实际索引含视频流，以 `codec_type` 过滤为准）；
- 没有 `FaceTime.mkv`。

### 10.4 组合 × 权限矩阵

| 组合 | 麦克风允许 | 系统音频允许 | 屏幕允许 | 预期 |
|---|---|---|---|---|
| 开+开 | 是 | 是 | 是 | 正常，3 音轨 MP4 |
| 开+开 | 否 | 是 | 是 | 仅对方，1 音轨，状态一句 |
| 开+开 | 是 | 否 | 是 | 仅麦克风，1 音轨，状态一句 |
| 开+开 | 是 | 是 | 否 | 双方声音无画面，状态一句 |
| 开+关 | — | 是 | 是 | 正常，1 音轨 |
| 开+关 | — | 否 | 是 | 失败，一句 + 重试 |
| 关+开 | 是 | — | 是 | 正常，1 音轨 |
| 关+开 | 否 | — | 是 | 失败，一句 + 重试 |
| 关+关 | — | — | — | 按钮禁用，不开始 |

### 10.5 不允许发布的情况

- 主界面仍有高级、设备选择、窗口选择、权限面板；
- 启动即请求权限，或拒绝后弹设置引导/权限矩阵；
- 仍生成 MKV 或把 MKV 作为主交付；
- 默认组合 MP4 不是三音轨，或单源组合生成了空轨/MKV，或 Mix 不是默认播放；
- 完成页出现第二行、MKV/WAV 行、播放按钮；
- 失败出现错误标题、错误码、多个操作按钮；
- 错误文案暴露 OSStatus 或 `tap/aggregate`；
- 麦克风仍只取 ch0 且未做增益/限幅；
- 真人通话未签字却移除 Beta 文字。

## 附录 A：与当前实现的差异（只记录，不在本文改代码）

本文是交互/产品文档，未修改任何 Swift 代码。审阅 `ContentView.swift`、`RecorderViewModel.swift` 与 Core 后，发现以下差异，供 Dev/QA 排期：

| 编号 | 现状 | V2 要求 | 影响 |
|---|---|---|---|
| A-01 | `ContentView` 有 `高级` DisclosureGroup、设备选择、监听输出、AEC、权限面板 | 全部删除；只留两个复选框、主按钮、状态、同意行、`…` 菜单 | 违反“轻巧小工具” |
| A-02 | `ContentView` 的“录制对方声音”副标题写“通过 HomePod Flow 虚拟声卡” | 删除副标题；process tap 不需要虚拟设备 | 主界面暴露已废弃方案 |
| A-03 | `onAppear` 调用 `ScreenRecorder.requestPermission()` | 首次打开不请求；点开始且需要画面时才请求 | 违反按需权限 |
| A-04 | `startBlockReason` 要求 `remoteDeviceUID`，没有 HomePod Flow 就禁止开始 | process tap 路径允许 `remoteDeviceUID` 为空 | 当前会挡住可用链路 |
| A-05 | `effectiveMonitorEnabled` / `effectiveTakeover` 跟随 `remoteAudioEnabled` | 删除监听与接管；不修改系统默认输出 | 当前会切换系统输出 |
| A-06 | `makeConfiguration()` 传 `remoteDeviceUID`，Core `validate()` 仍要求虚拟设备 | Core 允许 process tap 路径下 `remoteDeviceUID` 为空 | 入口仍被旧校验拦截 |
| A-07 | `MicCaptureRecorder` 对 >2 通道只取 `ch0`，无 +12 dB、无限幅 | 3 通道降单声道；+12 dB；limiter -1 dBFS | 麦克风偏小、只取单通道 |
| A-08 | `MediaMuxer` 生成 MKV + MP4；MP4 只有一条 Mix | 只生成 MP4；两项都开时 3 条 AAC；`disposition` 为 default / 0 / 0 | 输出格式与默认播放行为都不对 |
| A-09 | 完成页已有 `savedSummary` + Finder，但高级区和结果行附近有额外内容 | 只保留一行保存结果 + Finder；删除额外入口 | 需要清理周边 |
| A-10 | `ErrorMapper` 的 detail 暴露 OSStatus/fourCC/设备名 | 主界面只显示一句人话；技术详情只进 `…` 菜单 | 用户会看到技术错误 |
| A-11 | `ContentView` 权限状态用 StatusPill + 请求按钮 | 删除权限面板；拒绝时状态行一句话并降级 | 违反权限最小化 |
| A-12 | `ProcessTapCapture` 已实现 PID→process object、`CATapDescription(stereoMixdownOfProcesses:)`、私有 aggregate | 保留；增加启动阶段全零提示与完成行标注 | 链路可复用，缺产品门禁 |

### A.1 建议落地顺序

1. 先删 `ContentView` 的高级区、权限面板、设备/监听/AEC、窗口选择；
2. 解耦 `RecorderViewModel` 对 `remoteDeviceUID` 的硬依赖；
3. 权限改为按需请求，去掉启动时屏幕权限请求；
4. `MediaMuxer` 改为只输出 MP4 三音轨，设置 default disposition，停止生成 MKV；
5. 完成页收敛为一行 + Finder；
6. 错误映射收敛为一句 + 重试，技术详情进 `…` 菜单；
7. 麦克风 3ch→单声道 + 增益 + limiter；
8. 真人通话 1 分钟验收并签字。
