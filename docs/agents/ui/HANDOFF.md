# FaceTime Recorder — 极简 UI → Dev 交接

版本：2.0 · 日期：2026-11-07 · 来源：`UI_SPEC.md`、`WIREFRAMES.md`

状态：**极简版 UI 规范；实现未开始。FaceTime 远端音频仍为“待真人通话验证”。**

---

## 1. 一句话交接

主界面只保留：

- 两个声音开关；
- 一个开始/停止按钮；
- 一行状态 + 计时；
- 一行完成结果；
- 同意录音小字；
- 待验证小字；
- 底部 `高级`。

其余全部删除、移入高级或自动处理。

### 2.4 自动处理

| 行为 | 规则 |
|---|---|
| 系统输出接管 | `录制对方声音 == true` 时自动切换；停止/退出/下次启动恢复 |
| 监听 | 内部固定通路：送到**接管前的那台物理输出设备**；音量用 macOS 系统音量；不可选 |
| AEC | 麦克风开启时默认 Apple 语音处理；高级可关 |
| 自检 | 每次开始前自动 1 秒非静音自检；失败一句人话 |
| 画面 | V1 只录 FaceTime 窗口；启动时自动找；找不到才回退主显示器；无窗口列表 |
| 视频 | 始终录制；无开关 |
| 麦克风 | 默认系统默认输入；高级可换 |
| 权限 | 开始时按需触发系统弹窗；不自动点击/不绕过 |
| MP4 | 自动混音/封装 `FaceTime.mp4` |
| MKV | 自动生成多轨归档；主界面不展示 |
| 错误分类 | 自动判断权限/设备/自检/保存；主界面一句结论 |

## 4. 状态绑定

### 4.1 两个开关

```
recordRemote: Bool = true
recordMic: Bool = true
```

映射到 `RecorderConfiguration`：

| 配置字段 | 值 |
|---|---|
| `recordVideo` | `true`，始终 |
| `recordMicrophone` | `recordMic` |
| `microphoneUID` | 高级选择；默认系统默认输入 |
| `monitorEnabled` | `recordRemote`（只有录对方时才需要监听） |
| `monitorOutputUID` | **自动**：接管前系统默认输出如果是物理设备就用它；否则内置扬声器；不可选 |
| `monitorVolume` | `1.0`（unity）；音量由 macOS 系统音量控制，App 不提供滑杆 |
| `echoCancellation` | `recordMic ? .appleVoiceProcessing : .off`；高级可关 |
| `takeOverSystemOutput` | `recordRemote`，自动 |
| `remoteDeviceUID` | 高级选择；默认 HomePod Flow |
| `captureWindowID` / `captureDisplayID` | 自动：FaceTime 窗口；找不到才用主显示器；不列窗口 |
| `remoteChannelMode` | `.stereoDownmix`，UI 不暴露 |
| `outputDirectory` | 固定 `~/Movies/FaceTime Recorder` |
| `performSelfTest` | `recordRemote` |

### 4.2 可用性

```
canStart = (recordRemote || recordMic) && !busy
```

- 两个都关：主按钮禁用，状态 `至少选择一种声音`。
- 不检查“设备是否选齐”；设备自动解析，失败时一句人话。
- 录制中 `canStart == false`；主按钮改为停止。

### 4.3 状态映射

| Core | 主界面 |
|---|---|
| `idle` | 状态 `就绪`；按钮 `开始录制` |
| `preparing` | `正在准备…` + spinner；按钮禁用；开关禁用 |
| `recording` | 红点 + `录制中` + 计时；按钮 `停止并保存`；开关禁用 |
| `stopping` | `正在保存…`；计时冻结；按钮禁用 |
| `muxing` | 仍显示 `正在保存…`；不显示百分比 |
| `finished` | `已完成` + 结果行；按钮 `开始录制` |
| `failed` | 一句人话；按钮 `重试`；开关恢复可用 |

### 4.4 计时

- `recording/stopping/muxing`：`snapshot.elapsed`。
- `finished`：`result.durationSeconds`，冻结。
- **陷阱**：`RecorderEngine.startedAt` 在停止后不清零，`snapshot.elapsed` 会继续增长；完成页不要读它。
- `preparing`：不显示时间。
- `failed`：不显示时间。

### 4.5 完成结果

优先使用真实 `result.mp4URL`：

| 条件 | 结果行 |
|---|---|
| `recordRemote && recordMic` 且两轨非全零 | `已保存 FaceTime.mp4（双方声音）` |
| 仅 `recordRemote` 且远端非全零 | `已保存 FaceTime.mp4（对方声音）` |
| 仅 `recordMic` 且麦克风非全零 | `已保存 FaceTime.mp4（我的声音）` |
| 对应音轨全零 | `已保存 FaceTime.mp4（未检测到声音）` |
| `mp4URL == nil` | `已保存原始文件，但 MP4 生成失败` + `查看高级` |

规则：

- 没有真实 MP4 不显示“已保存 FaceTime.mp4”。
- 不显示文件大小、轨道数、封装命令。
- `在 Finder 中显示` 指向 `result.sessionDirectory`；目录不存在则隐藏。
- 不自动打开 Finder/播放器。

### 4.6 失败

`failed` 时主界面只显示一句：

- 麦克风权限：`没有麦克风权限。请在系统设置中允许，或关闭“录制我的麦克风”。`
- 屏幕权限：`没有屏幕录制权限。请在系统设置中允许后重新开始。`
- 远端无声音：`没有听到对方的声音。请确认 FaceTime 正在通话，并允许系统音频录制。`
- 设备缺失：`没有找到 HomePod Flow 虚拟声卡。请确认它已安装。`
- MP4 失败：`已保存原始文件，但 MP4 生成失败。请查看高级 → 诊断。`
- 保存失败：`无法保存文件。请检查磁盘空间后重试。`
- 兜底：`录制没有开始。请重试；仍失败请查看高级 → 诊断。`

不要在主界面显示 OSStatus、错误编号、FFmpeg、8ch、路由术语；这些只进高级诊断。

### 4.7 权限

- 麦克风：`AVCaptureDevice.authorizationStatus(for: .audio)`；开始前按需请求。
- 屏幕录制：`CGPreflightScreenCaptureAccess()`；开始前按需请求。
- 系统音频：**无法预检**；由自动自检结果推导；高级里只能写“由自检确认”。
- 权限失败不弹自定义大对话框；主界面一句人话 + 高级详情。

### 4.8 自动路由

Dev 需要：

1. `recordRemote == true` 时：
   - 解析 HomePod Flow 设备；没有则失败一句人话；
   - 自动 `takeOverSystemOutput = true`；
   - 接管前记录当前系统默认输出；如果是物理设备，监听就送到它；否则回退内置扬声器；
   - `monitorVolume = 1.0`，音量完全交给 macOS 系统音量；不提供 App 内滑杆；
   - 自动自检；
   - 开始录制。
2. `recordRemote == false` 时：
   - 不接管系统输出；
   - 不要求 HomePod Flow；
   - 只录麦克风 + 画面。
3. 画面：
   - 调用 `ScreenRecorder.listWindows()`；
   - 有 FaceTime 窗口 → 选它（优先唯一窗口）；
   - 没有 FaceTime 窗口 → 主显示器；
   - 每次开始前重新查找一次，并更新高级里的只读 `画面：…` 状态；
   - 不弹选择器、不自动选其他 App 窗口。
4. 停止/退出：
   - 恢复默认输出；
   - 恢复失败只进高级诊断，不在主界面吓用户。
5. 崩溃恢复：
   - 启动时调用 `recoverStaleOutputLease()`；
   - 不在主界面展示技术细节。

## 6. Core/API 缺口

| ID | 缺口 | 说明 | 阻塞 |
|---|---|---|---|
| API-00 | **`recordRemote` 配置/可选远端轨** | 关闭“录制对方声音”时不得启动远端 tap、远端轨或接管；当前 `RecorderConfiguration` 无此字段，Engine 总是录远端 | **P0** |
| API-01 | **MP4 混音/封装 + `mp4URL`** | 结果行要求 `已保存 FaceTime.mp4（…）`；当前 `MediaMuxer` 只产出 MKV，`RecordingResult` 无 `mp4URL` | **P0** |
| API-02 | **MKV 混音轨** | 高级里若写“多轨归档（混音/远端/麦克风）”，MKV 必须真的有混音轨 | P1 |
| API-03 | 结果静音判定 | “双方声音”需要远端/麦克风非全零；建议结果带 `remoteSilent/micSilent` | P1 |
| API-04 | 自动窗口查找 | 内部调用 `listWindows()` 找 FaceTime 窗口；找不到回退主显示器；UI 不展示窗口列表 | P1 |
| API-05 | 接管前输出记忆 + 音量验证 | 接管前记录物理输出 UID 作为监听目标；非物理则回退内置扬声器；不可由用户选择。还需验证接管后 macOS 音量键仍作用于该物理设备；若只控制默认虚拟设备，Dev 需修正路由/音量策略，但不得加回 App 滑杆 | P1 |
| API-06 | 恢复租约结果 | 启动恢复默认输出，UI 不需要展示，但 Dev 要知道成功/失败 | P2 |
| API-07 | 只读事件/日志 | 高级“查看日志”需要真实事件；当前 `events` 私有 | P2 |
| API-08 | 监听状态详情 | 高级权限/诊断需要 AEC 是否启用、监听设备实际名称 | P2 |

说明：

- 旧版要求的“录制中监听开关/音量”已随极简 UI 删除；不再需要实时监听控制 API（不要把旧编号套到本表）。
- 没有 API-00，关闭“录制对方声音”只是 UI 假象；必须从采集层跳过远端。
- 没有 API-01，结果页只能显示失败句；不能伪造 `FaceTime.mp4`。
- 主界面不显示任何 API 缺口；缺什么都在高级诊断里体现。
